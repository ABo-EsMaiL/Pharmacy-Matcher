Entity resolution for pharmacy drug names—mapping local/unstructured strings to **RxNorm** concepts (which represent the standard **Ingredient + Strength + Dose Form**)—is a critical task for healthcare interoperability[1][2]. 

Modern approaches typically combine traditional deterministic methods with LLM-based parsing to handle the high variability in medication naming[3][4].

### 1. The Core Challenge: Drug Name Heterogeneity
Drug names vary due to misspellings, abbreviations (e.g., "MTX" for methotrexate), incomplete information (missing strength or form), and synonym usage (brand vs. generic)[5][6][2]. RxNorm standardizes these into unique **RXCUIs**[6][7].

### 2. Standard Approaches for Resolution
*   **Tiered Resolution Strategy:** Most robust systems follow a fallback hierarchy[5][8]:
    1.  **Exact Match:** Uses normalized strings to map standard names directly to an RXCUI[5][9].
    2.  **Fuzzy Matching:** Utilizes the RxNorm API’s `getApproximateMatch` to handle typos, partial names, and minor variations[5][9]. This tool performs drug-centric adjustments like ignoring word order and case, and applying stemming[9].
    3.  **Identifier Lookup:** Directly resolves NDC codes or specific RxCUIs if available[5][10].
    4.  **Label Fallback:** Queries resources like `openFDA` for cases where RxNorm resolution fails[5][8].

### 3. LLM-Assisted Entity Resolution
LLMs have significantly improved performance in "noisy" environments (e.g., clinical notes or patient-reported data) where traditional algorithms struggle[3][11].
*   **Parsing Unstructured Data:** LLMs excel at extracting drug name, strength, and dose form from complex strings where traditional tokenizers fail[3][12].
*   **Hybrid Pipelines:** Recent research suggests a hybrid approach where an LLM performs the initial normalization/parsing, and a backend system performs the deterministic mapping to RxNorm, often leveraging Retrieval-Augmented Generation (RAG) to ensure accuracy[3][11].
*   **Clinical NLP Libraries:** Libraries like **Spark NLP for Healthcare** offer specialized entity resolver models trained to map clinical entities directly to RxNorm codes[13][14]. These models often utilize BERT-based embeddings (`sbiobert`) to understand the semantic context of drug entities[13].

### 4. Practical Implementation Considerations
*   **Data Quality:** Even with LLMs, missing components (e.g., a strength missing from a "Promethazine-Codeine" string) are common causes of unmappable records[12].
*   **Confidence Scoring:** Systems should implement confidence thresholds. Low-confidence matches should be flagged for human review, especially when distinguishing between salt forms (e.g., *Warfarin Sodium* vs. *Warfarin*) or similar-sounding brand names[3][4].
*   **Tooling:**
    *   **RxNav/RxNorm API:** The official NLM interface for accessing the RxNorm dataset and performing approximate matching[9][15].
    *   **Spark NLP / OHDSI:** Frameworks widely used for large-scale clinical data transformation and OMOP Common Data Model alignment[2][11][4].
